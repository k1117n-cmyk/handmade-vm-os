## 003-movi-test.c の解説

`003-movi-test.c` は、小さな自作VMの `MOVI` 命令を単独で確認するテストです。

`MOVI` は immediate、つまり「命令の中に直接入っている数値」をレジスタへ入れる命令です。

このテストでは、メモリに次の1命令を置いています。

```asm
MOVI R7, 0x12345
```

命令値としては次の4バイトです。

```text
40 71 23 45
```

32bit命令として見ると、これは `0x40712345` になります。

## VMの状態

冒頭でVMの状態を用意しています。

```c
uint8_t memory[1024 * 1024] = {0};
uint32_t pc = 0x00000000;
uint32_t regs[8] = {0};
```

意味は次の通りです。

- `memory`: 1MBのメモリ。1要素が `uint8_t` なので1バイト単位
- `pc`: プログラムカウンタ。次に読む命令のアドレス
- `regs`: 32bitレジスタ8本、`R0` から `R7`

このテストでは実行ループや `HALT` はありません。1命令だけ読み、実行して終わります。

## メモリに置かれる命令

次の部分で、命令をメモリの先頭に直接書き込んでいます。

```c
memory[0x00000000] = 0x40;
memory[0x00000001] = 0x71;
memory[0x00000002] = 0x23;
memory[0x00000003] = 0x45;
```

メモリ配置としては次の通りです。

```text
0x00000000: 40 71 23 45    MOVI R7, 0x12345
```

命令は4バイト固定長なので、この4バイトを1つの命令として読みます。

## 命令の読み取り

VMは1命令を4バイト固定長として読んでいます。

```c
uint32_t inst =
    ((uint32_t)memory[pc] << 24) |
    ((uint32_t)memory[pc + 1] << 16) |
    ((uint32_t)memory[pc + 2] << 8) |
    ((uint32_t)memory[pc + 3]);

pc += 4;
```

メモリ上の4バイトをビッグエンディアンとして `uint32_t` に合成しています。

今回のメモリは、

```text
memory[0] = 0x40
memory[1] = 0x71
memory[2] = 0x23
memory[3] = 0x45
```

なので、命令値は次のようになります。

```text
inst = 0x40712345
```

読み終わった後、`pc += 4` によって `pc` は次の命令位置へ進みます。

```text
pc = 0x00000004
```

ただし、このテストでは次の命令は読まず、1命令だけで終了します。

## 命令フォーマット

このテストでは、32bit命令を次のような配置として扱っています。

```text
bits 31..24: opcode
bits 23..20: rd
bits 19..0 : imm
```

コードでは次のように分解しています。

```c
uint8_t opcode = (inst >> 24) & 0xFF;
uint8_t rd = (inst >> 20) & 0x0F;
uint32_t imm = inst & 0x000FFFFF;
```

`MOVI` の仕様としては、上位8bitの `opcode` が `0x40` の命令を `MOVI` として扱っています。

```text
[ opcode:8 ][ rd:4 ][ imm:20 ]
```

## opcode の取り出し

```c
uint8_t opcode = (inst >> 24) & 0xFF;
```

`inst` は `0x40712345` です。

右に24bitシフトすると、一番上の1バイトだけが下位に来ます。

```text
0x40712345 >> 24 = 0x40
```

したがって、

```text
opcode = 0x40
```

になります。

この `0x40` が `MOVI` を表しています。

## rd の取り出し

```c
uint8_t rd = (inst >> 20) & 0x0F;
```

`rd` は destination register、つまり書き込み先レジスタ番号です。

`inst = 0x40712345` を桁で見ると次の通りです。

```text
0x 40 7 12345
    |  |   |
    |  |   +-- imm = 0x12345
    |  +------ rd  = 7
    +--------- opcode = 0x40
```

したがって、

```text
rd = 7
```

になります。

## imm の取り出し

```c
uint32_t imm = inst & 0x000FFFFF;
```

`imm` は命令の下位20bitです。

`0x000FFFFF` は下位20bitだけが `1` になっているマスクです。

```text
instruction = 0x40712345
mask        = 0x000FFFFF
result      = 0x00012345
```

したがって、

```text
imm = 0x12345
```

になります。

## MOVI の実行

decode した結果を使って、`MOVI` を実行します。

```c
if (opcode == 0x40) {
    regs[rd] = imm;
}
```

今回の値は、

```text
opcode = 0x40
rd     = 7
imm    = 0x12345
```

なので、実際には次の処理になります。

```c
regs[7] = 0x12345;
```

つまり `R7 = 0x12345` になります。

## 表示している内容

最後に、命令値と `R7` の値を表示しています。

```c
printf("inst=%08X\n", inst);
printf("R7=%05X\n", regs[7]);
```

期待される出力は次の通りです。

```text
inst=40712345
R7=12345
```

`%08X` は8桁の16進数で表示します。`%05X` は5桁の16進数で表示します。

## 整理

このコードで重要なのは、1つの命令について fetch、decode、execute の最小形を試している点です。

```text
fetch: memory[pc] から4バイトを読み、inst = 0x40712345 を作る
decode: inst から opcode=0x40, rd=7, imm=0x12345 を取り出す
execute: opcode が 0x40 なら regs[rd] = imm を行う
```

要するにこのコードは、`MOVI R7, 0x12345` という命令を読み取り、`R7` に `0x12345` を入れられるかを確認する最小テストです。
