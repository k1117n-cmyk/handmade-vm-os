## 002-fetch-test.c の解説

`002-fetch-test.c` は、小さな自作VMの `fetch` 処理を確認するテストです。

`fetch` は、`pc` が指しているメモリアドレスから命令を読み出す処理です。このVMでは1命令を4バイト固定長として扱うので、`pc` が指す場所から4バイトを読み、1つの32bit命令に組み立てます。

このテストでは、メモリの先頭に次の4バイトを置いています。

```text
01 00 00 00
```

これを32bit命令として読むと、`0x01000000` になります。

## VMの状態

冒頭で、fetch に必要な最小限の状態を用意しています。

```c
uint8_t memory[1024 * 1024] = {0};
uint32_t pc = 0x00000000;
```

意味は次の通りです。

- `memory`: 1MBのメモリ。1要素が `uint8_t` なので1バイト単位
- `pc`: プログラムカウンタ。次に読む命令のアドレス

このテストではレジスタや実行ループはありません。目的は命令の読み取りだけです。

## メモリに置かれる命令

次の部分で、命令らしき4バイトをメモリの先頭に直接書き込んでいます。

```c
memory[0x00000000] = 0x01;
memory[0x00000001] = 0x00;
memory[0x00000002] = 0x00;
memory[0x00000003] = 0x00;
```

メモリ配置としては次の通りです。

```text
0x00000000: 01
0x00000001: 00
0x00000002: 00
0x00000003: 00
```

この4バイトを1つの命令として読みます。

## fetch 前の PC

命令を読む前に、現在の `pc` を表示しています。

```c
printf("PC before=%08X\n", pc);
```

初期値は次の通りです。

```c
uint32_t pc = 0x00000000;
```

なので、表示は次のようになります。

```text
PC before=00000000
```

## 命令の読み取り

この部分が fetch の中心です。

```c
uint32_t inst =
    ((uint32_t)memory[pc] << 24) |
    ((uint32_t)memory[pc + 1] << 16) |
    ((uint32_t)memory[pc + 2] << 8) |
    ((uint32_t)memory[pc + 3]);
```

`pc` は `0x00000000` なので、実際には次の4バイトを読んでいます。

```c
memory[0]
memory[1]
memory[2]
memory[3]
```

それぞれの値は次の通りです。

```text
memory[0] = 0x01
memory[1] = 0x00
memory[2] = 0x00
memory[3] = 0x00
```

このVMでは、先頭のバイトを32bit値の一番上に置くビッグエンディアンの形で命令を組み立てています。

```text
memory[pc]     << 24  -> 0x01000000
memory[pc + 1] << 16  -> 0x00000000
memory[pc + 2] << 8   -> 0x00000000
memory[pc + 3]        -> 0x00000000
```

これらを `|` で合成すると、次の値になります。

```text
inst = 0x01000000
```

## uint32_t へのキャスト

各バイトをシフトする前に、`uint32_t` にキャストしています。

```c
((uint32_t)memory[pc] << 24)
```

`memory` の要素は `uint8_t` なので、1バイトの値です。それを32bit命令の上位バイトへ移動させるために、先に `uint32_t` に広げています。

このキャストを入れておくと、「1バイトの値を32bit命令の部品として扱っている」という意図が明確になります。

## PCを進める

命令を1つ読んだ後、`pc` を4進めています。

```c
pc += 4;
```

このVMでは1命令が4バイトなので、次の命令は4バイト後にあります。

今回の初期値は `0x00000000` なので、fetch 後は次の値になります。

```text
pc = 0x00000004
```

## opcode の確認

次に、命令の先頭バイトを `opcode` として取り出しています。

```c
uint8_t opcode = memory[0x00000000];
```

今回の先頭バイトは `0x01` なので、

```text
opcode = 0x01
```

になります。

この段階では、まだ本格的な decode はしていません。単に「命令の最初の1バイトは何か」を確認しています。

## 表示している内容

最後に、fetch した命令、opcode、fetch 後の `pc` を表示しています。

```c
printf("INST=%08X\n", inst);
printf("OPCODE=%02X\n", opcode);
printf("PC after =%08X\n", pc);
```

期待される出力は次の通りです。

```text
PC before=00000000
INST=01000000
OPCODE=01
PC after =00000004
```

`%08X` は8桁の16進数で表示します。`%02X` は2桁の16進数で表示します。

## 整理

このコードで確認しているのは、次の3点です。

- `pc` が指す場所から4バイトを読む
- `01 00 00 00` を `0x01000000` として組み立てる
- 1命令を読んだ後に `pc` を4進める

要するにこのコードは、VMの命令実行の最初の段階である fetch、つまり「メモリから32bit命令を1つ読む処理」を確認する最小テストです。
