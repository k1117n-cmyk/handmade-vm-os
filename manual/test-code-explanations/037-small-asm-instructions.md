# Day 37: small-asmでメモリ操作とサブルーチンを書く

対象は `tools/small-asm.c` と `tools/test-small-asm.py`。VM命令の追加ではなく、ホスト側の変換ツールの拡張です。[仕様カード](../specs/037-small-asm-instructions.md)に構文をまとめています。

## 追加する5命令

Day 36のwriterが使うLDB、STB、INC、CALLI、RETを追加します。既存7命令と合わせて、echoの命令部分に必要な12命令を数値で書けます。文字列やラベルはまだ書けません。

`parse_memory_register`は長さ4、先頭`[`、末尾`]`を確認します。中の2文字を取り出し、既存の`parse_register`でR0〜R7か検査します。LDBは第2オペランド、STBは第1オペランドにこの関数を使います。角括弧は機械語に残らず、命令名とレジスタ番号が命令値へ変換されます。

```text
LDB R2, [R7] → 0x30270000 → 30 27 00 00
STB [R7], R2 → 0x31720000 → 31 72 00 00
INC R7       → 0x20700000 → 20 70 00 00
CALLI 0x20   → 0x69000020 → 69 00 00 20
RET          → 0x02000000 → 02 00 00 00
```

STBのrdはアドレスを保持するレジスタです。`rd`という名前だけで「レジスタへの書き込み」と判断しないようにします。

INCはレジスタ1個、RETはオペランドなしを検査します。CALLIは既存のJUMP系と同じ即値解析を使い、opを9にします。文字列の分割、大小文字の正規化、コメント除去、big-endian出力は既存処理を再利用します。

## サンプルのメモリとPC

`programs/asm-memory-call.asm`は14命令、56 byteです。0x500に65（A）、0x501に66（B）をSTBで書きます。INCでR1を動かした後、読み取り前に0x500へ戻す点に注意します。

| 場所 | 命令 | 動作 |
|---|---|---|
| 0x1C | CALLI 0x28 | 戻り先0x20を保存 |
| 0x20 | CALLI 0x28 | 戻り先0x24を保存 |
| 0x24 | HALT | メイン処理を終了 |
| 0x28 | LDB R0, [R1] | 現在位置の1 byteを読む |
| 0x2C | SYSCALL 0 | 1文字と改行を表示 |
| 0x30 | INC R1 | 次のbyteへ進む |
| 0x34 | RET | 呼び出し元へ戻る |

1回目はAを表示してR1=0x501、2回目はBを表示してR1=0x502になります。SPは各CALLIで0x100000から0x0FFFFCへ減り、RETで元へ戻ります。HALTはサブルーチンの直前にあり、戻った後にそのままサブルーチンへ流れ込むことを防ぎます。

```sh
make run-asm-memory-call
```

ビルド表示を除いた出力:

```text
A
B
CPU halted.
```

## テストの分け方

```sh
make test-small-asm
```

59ケースで、次を確認します。

- 固定の期待バイト列との一致。rdとrsを異なる値にし、配置の逆転も検出する。
- R0/R7、即値0/0xFFFFF、大小文字、コメント、省略カンマなどの既存字句規則。
- 欠けたオペランド、余分なオペランド、R8、角括弧の誤り、即値範囲外、未対応の名前・命令・指示、行長超過の拒否。
- 既存5サンプルが保存済み.binと一致すること。
- Day 36のread_lineとstring_equalを数値で書いた31命令が、writer生成物の0x09C〜0x117と一致すること。別にCALLIも0x084の命令と照合する。
- 新サンプルの全14命令の値と、実VMでの出力・標準エラー・終了コード。

一時ファイルはPythonのTemporaryDirectoryへ置き、起動ごとに5秒の制限を設けています。writerとの比較用の命令断片は、元の絶対アドレスを保ったままバイト列だけ照合します。その断片を先頭アドレス0で実行するテストではありません。
