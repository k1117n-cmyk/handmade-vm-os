# Day 38: small-asmのラベル解決を読む

対象は `tools/small-asm.c` と `tools/test-small-asm-labels.py` です。VM命令を増やす部品テストではなく、ホスト側ツールの入力から出力までを確認します。[仕様カード](../specs/038-small-asm-labels.md)も参照してください。

## 数値版と同じ命令列を作る

`programs/asm-label-call.asm` はDay 37の数値版を残したまま追加した比較用サンプルです。

```asm
CALLI print_byte
CALLI print_byte
HALT

print_byte:
LDB R0, [R1]
SYSCALL 0
INC R1
RET
```

この抜粋の前に7命令あります。ラベルの前にある命令は合計10個なので、`print_byte` のアドレスは10×4 = 40 = 0x28です。ラベルの行は命令ではなく、出力を増やしません。CALLIの命令値は両方とも0x69000028です。

```sh
make run-asm-label-call
make test-small-asm test-small-asm-labels
cmp programs/asm-memory-call.bin programs/asm-label-call.bin
```

出力はA / B / CPU halted.。cmpは一致時に何も表示せず終了コード0になります。

## 名前の表と2回の読み取り

`Label` は名前とアドレスの組です。`labels` に最大256組を保存し、`find_label` は先頭から名前を比較します。この規模では、複雑な検索構造を用意せず配列を順に調べます。

`prepare_line` はコメントを除去し、大小文字を統一して、コロンの左側を名前として検査します。1回目だけ表へ登録します。登録アドレスは `instruction_count * 4` です。同じ行に続く命令があれば、それを `assemble_line` へ渡します。

1回目も命令の構文を検査しますが、`parse_target` は有効な名前に仮の0を返します。この命令値はファイルへ書かず、命令数だけ数えます。入力を `fseek` で先頭へ戻すと、表には後ろにある定義も入っています。

2回目の `parse_target` は数値なら従来の `parse_imm20`、名前なら表を検索してアドレスを返します。定義がなければ `undefined label`。アドレスが決まった後の命令値の組み立てとbig-endian出力は従来通りです。

## エラーと上限

名前の長さは63文字、定義数は256個。ASCII英字とアンダースコアで始めます。`loop` と `LOOP` の重複も拒否します。複数ラベルを同じ行へ書く構文、式、データ指示は未対応です。

20bitで表せるアドレスの最後の命令境界は0xFFFFCです。262144命令の後へラベルを書くと0x100000になるので拒否します。この制限は出力形式の上限であり、VMのメモリ容量やスタックとの衝突を検査するものではありません。

変換途中の命令は `tmpfile` で作った一時ファイルへ書きます。2回の変換が成功してから指定出力を開くため、未定義の参照が後半に見つかっても既存ファイルは変わりません。出力へのコピーやクローズの失敗も確認しますが、I/Oエラー時の完全な原子的置換は行いません。

## テストの読み方

- 既存テストは57ケース。以前の59ケースから、ラベル単独行と未定義CALLIの2ケースを今回のテストへ移しました。
- ラベル用は44ケース。全4命令の前後参照、空白・コメント・CRLF、別名、予約語と同名、数値との混在、末尾ラベルを固定命令値と比較します。
- 不正入力は、出力が存在しない場合と既存内容がある場合の両方で、行番号・診断・終了コード・出力の保持を確認します。
- 63/64文字、256/257定義、20bit上限の内外を確認します。
- Day 37の数値版とバイト比較し、さらにHALTの後へINC R7を挿入した版では両CALLIが0x2Cへ変化することを確認します。挿入命令は実行されません。
- サンプル、挿入版、JZ/JNZを使うループをVMで実行し、A / B / CPU halted.を照合します。

文字列データを配置する機能は次の段階です。MOVIへラベルを渡す仕様も、その用途と合わせて別に決めます。
