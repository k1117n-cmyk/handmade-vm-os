# Day 44 別プログラムの起動と復帰

## 状態と範囲

2026-11-11、ユーザーが Muse 経由の伝達で推奨案を承認した。以下は確定した仕様。
親プログラムの `Command> ` から固定の子プログラムを起動し、子の終了後に親のコマンド入力を続ける。
実装の開始指示により、ロード部品の確認、VM統合、親子サンプルの入出力検証を行う。

基準は [機械状態](000-machine-state.md)、[HALT](001-halt.md)、
[外部バイナリローダー](021-binary-loader.md)、[host側monitor](031-monitor-mode.md)、
[Day 43のコマンドと保存・読み込み](043-line-storage.md)。

## 起動方式

hostのsyscallが初期化した独立した子VMへバイナリを読み込み、同期実行する。
子は既存のPC=0の形式を使う。子の終了後は親のメモリとスタックを保持したまま親へ結果を返す。

## コマンドとファイル

- 新サンプルは親 `programs/program-launcher.asm` / `.bin` と、子 `programs/run-child.asm` / `.bin`。
  親はDay 43のコマンドを継承し、`run` とhelpの1行 `run: start run-child.bin` を加える。
- `run` はVMプロセスの作業ディレクトリから `programs/run-child.bin` を起動する。
  コマンド名は小文字。先頭と末尾の半角空白は受理し、`run x` は `Unknown command` と表示する。
  入力上限・CR・EOF・NULはDay 43の扱いを継承する。
- 正常終了後は親が `Run finished.`、起動失敗または異常停止後は `Run failed.` をそれぞれLF付きで表示し、
  次の `Command> ` へ戻る。子の出力と既存の停止・エラー診断は、その通知より先に表示される。
- 子の入力は従来の生バイナリ形式。先頭に1命令分ある4 byteから1 MiBまでを受理する。
  末尾には文字列データを置ける。ロード前に命令列全体の妥当性は判定せず、実行時は既存VMの命令規則を適用する。

## 呼び出し規約

| 項目 | 確定した仕様 |
|---|---|
| 入口 | `SYSCALL 6`（`60 00 00 06`）。入力レジスタなし。親は子の終了まで待つ |
| 子の初期状態 | 子用の独立した1 MiBのメモリをゼロ初期化し、アドレス0からファイルを格納。PC=0、SP=0x100000、R0〜R7=0、zero flag=false、running=true |
| 正常終了 | 子が既存のHALTを実行し、`CPU halted.` を表示したら親のR0へ0を返す |
| 失敗 | 子VMの確保失敗、ファイルのopen/read/close失敗、容量外、または子がHALT以外で停止した場合は親のR0へ1を返す。停止の例は不正命令、範囲外のメモリ書き込み、標準入力EOF。ロードに失敗した子は実行しない |
| 親への復帰 | R0だけへ結果を書き、syscallの次の命令から続ける。親のR1〜R7、SP、zero flag、runningと全メモリ（命令・入力・編集領域・スタックを含む）を保持する |
| 子からの再起動要求 | 子の `SYSCALL 6` はファイルを開かず、子のR0へ1を返す。子はその次の命令から続けられる |
| host資源 | 標準入出力と作業ディレクトリは親子で共有する。子のsyscall 0〜5は既存の規約を使う。子が消費した入力や `line.txt` への書き込みは復帰後も有効 |

子VMは起動ごとに初期化し、起動の成否にかかわらず使用済みの領域と開いたファイルを解放する。
HALTも実行時停止も起きなければ親は待ち続ける。実行時間制限、任意パス、引数・終了値の受け渡し、
多重起動、並行実行、同一VMへの配置、仮想ディスクは後に回す。

## 実装時の検証と生成物

1. ロード部品を、欠落・読み取りとcloseの失敗、0〜3 byte、4 byte、1 MiB、1 MiB超で確認する。
   子用の初期状態と、ロード失敗時に子の命令が実行されないことも確認する。
2. VM統合後、正常HALT・実行エラー・EOF・子からの起動要求と、復帰時の親状態を検証する。
   親のR0と復帰PCに加え、全メモリ、R1〜R7、SP、zero flag、runningを照合する。
3. 新サンプルで `set keep → run → show → quit`、起動失敗後の再入力、連続起動時の子の初期化、
   共有する標準入力と `line.txt` の扱い、引数拒否、親の終了後のhost側monitor復帰を確認する。
   Day 43までの回帰セットも実行する。
4. 親は入力0x500〜0x53Fと編集0x600〜0x63Fを継承し、命令・文字列末尾の次を0x500以下に収める。
   子のサンプルは `MOVI R0, 65`、`SYSCALL 0`、`HALT` の3命令・12 byteとし、
   `A` と `CPU halted.` をそれぞれLF付きで表示する。親の命令数・binサイズは実装後に測定する。
   親子それぞれのbinと再アセンブルしたbinの全byte一致を確認する。
5. 実行確認後にREADME・manual索引・解説・WORKLOG・HANDOFFを更新する。

## 部品の実装規約と検証対応

固定パスのロード部品は `notes/program-launch.h` の `load_child_program(memory, capacity)` とする。
初期化済み子メモリの先頭と容量を受け、4 byte以上かつ容量以下を読み、read・末尾確認・closeが成功した場合にtrueを返す。
失敗時はfalse。失敗時の子メモリの保持は要求せず、呼び出し側がその子を実行せず破棄する。
子の初期化には既存の `init_vm` を使用する。子VMはhostのヒープに確保して終了後に解放する。
ロード部品自体は画面出力を行わず、親サンプルが結果を表示する。

部品テストは一時ディレクトリの `programs/run-child.bin` を使用し、stdio置換でread・末尾確認・close失敗を再現する。
統合後は確保失敗も置換で再現する。fetch/decode/execute経由でsyscallを呼び、親のメモリ全体・レジスタ・SP・フラグ・PC・runningを照合する。
