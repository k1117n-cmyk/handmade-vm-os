# Day 37: small-asmの命令対応拡張

```text
名前: small-asm instruction extension
分類: ホスト側の開発補助ツール
目的: Day 36のwriterが使う全命令を数値オペランドで変換する
追加: LDB / STB / INC / CALLI / RET
出力: 1命令4 byte、big-endian、先頭から順に配置
VM本体・命令番号・実行時の意味: 変更なし
成功条件: 命令値とwriterの出力に一致し、生成したサンプルがAとBを表示する
```

## 構文と命令値

| 構文 | 命令値 | 既存VMでの意味 |
|---|---|---|
| `LDB Rd, [Rs]` | `0x30000000 \| (rd << 20) \| (rs << 16)` | Rsの指す1 byteをRdへ読む |
| `STB [Rd], Rs` | `0x31000000 \| (rd << 20) \| (rs << 16)` | Rsの下位8 bitをRdの指す場所へ書く |
| `INC Rd` | `0x20000000 \| (rd << 20)` | Rdを1増やす |
| `CALLI imm` | `0x69000000 \| imm` | 次のPCをスタックへ保存しimmへ移る |
| `RET` | `0x02000000` | 保存したPCへ戻る |

レジスタはR0〜R7。命令名とレジスタ名は大小文字を区別しない。メモリ側の角括弧は必須で、`[R1]`の内部に空白は入れない。`LDB R0, R1`、`STB R1, R0`、括弧の欠落・逆転・二重化はエラー。既存と同じくカンマは空白へ置き換えるので、省略や連続カンマも区切りとして受け入れる。厳密なカンマ文法への変更は行わない。

CALLIの即値は既存のJUMPと同じparse_imm20で読み、0〜0xFFFFFを受け付ける。基数0のstrtoulを使うので、10進、0x付き16進、先頭0の8進、先頭の+を受け付ける。既存仕様を引き継ぎ、`-0`も0として受け付ける。範囲外、数値以外、余分なオペランドを拒否する。命令境界や配置先が実行可能かは検査しない。サンプルでは必ず4 byte境界の実在する命令を指定する。

空行、`;`と`#`以降のコメント、行長制限、診断形式は既存通り。不正命令では入力パス・行番号と診断を標準エラーへ出し、終了コード1を返す。失敗時も途中までの出力ファイルが残る既存動作を引き継ぐ。失敗した出力は実行しない。

## 範囲

既存7命令を維持し、合計12命令に対応する。ラベル、文字列、配置指示、式、その他のVM命令は今回追加しない。echo全体には文字列と配置が必要なので、専用writerを引き続き使う。

`programs/asm-memory-call.asm`は0x500と0x501へA/Bを書き、同じサブルーチンを2回呼ぶ14命令のサンプル。呼び出し先は0x28。1 byteを読んでSYSCALL 0で表示し、INCで次へ進めてRETする。

## 検証

`make test-small-asm`で固定の命令値、レジスタ境界、即値境界、構文エラー、既存5サンプルのバイト一致、Day 36のread_lineとstring_equalの命令列一致、生成サンプルのVM実行を確認する。VM命令追加ではないため、notesの部品テストは追加せず、実際のsmall-asmをPythonから起動する。
