# Day 38: small-asmのラベル対応

```text
分類: ホスト側の開発補助ツール
目的: 固定長命令列の分岐先・呼び出し先を名前で指定する
出力: 1命令4 byte、big-endian、先頭アドレス0（従来通り）
成功条件: 数値版と同じbyte列、前方参照の解決、重複・未定義の拒否
```

## 名前と定義

- ASCIIの英字または `_` で始め、以後は英数字または `_`。1〜63文字。
- 大文字・小文字は区別しない。`loop` と `LOOP` は同じ名前。
- 行頭の空白を除いた位置に `name:` を書く。コロンの前の空白も許す。
- ラベルだけの行、`name: HALT` のように命令を続ける行の両方を許す。1行1定義。
- 空行・コメント・ラベル自体はbyteを消費しない。定義位置は、それまでの命令数×4。
- 別の行で異なる名前を同じ位置へ付けてもよい。同じ名前の再定義は同じ位置でもエラー。
- 最大256定義。命令名・レジスタ名も名前として許す（`HALT: JUMP HALT`）。コロンとオペランドの位置で区別できる。

## 参照

`JUMP / JZ / JNZ / CALLI` の宛先だけに、数値またはラベル名を許す。`MOVI` と `SYSCALL` は数値のみ。前方・後方参照を許す。数値式、`loop+4`、文字列、配置指示は扱わない。

数値の読み方・20bit範囲・カンマの区切りはDay 37を維持する。数値宛先の命令境界や実行可能性は検査しない。ラベルは0〜0xFFFFFの範囲で定義する。命令列は最大262144命令（1 MiB）。最大命令の先頭は0xFFFFCで、1 MiB直後のラベルは範囲外。通常の末尾ラベルは許すが、その位置に命令を置かないままジャンプすることは推奨しない。アセンブラの形式上の上限とVMの利用可能メモリは別で、実行可能性を保証する値ではない。

## 2回の読み取り

1回目はコメントを除去して大文字へ揃え、名前とアドレスの表を作る。命令の構文を検査して命令数を数える。この段階のラベル参照は仮の0とし、出力しない。

2回目は同じ入力を先頭から読み、全定義が入った表で参照を解決して命令値を生成する。入力は先頭へ戻せるファイルとする。変換中の入力変更は扱わない。

## エラーと出力

入力パスと行番号を付け、標準エラーへ診断を出して終了コード1を返す。重複、未定義、名前の不正、定義数超過、アドレス超過を区別する。従来の不正命令・行長エラーも維持する。

2回目の結果は一時ファイルへ置き、全行の変換成功後に指定出力へ書く。構文・ラベルエラーでは指定出力を新規作成・上書きしない。出力時のI/Oエラーでは途中のファイルが残り得る。成功時だけ命令数を表示する。

## サンプルと検証

`programs/asm-label-call.asm` はDay 37の2個の `CALLI 0x28` を `CALLI print_byte` に変更し、LDBの前にラベルを付ける。数値版の56 byteと一致し、A / B / CPU halted.を表示する。

`make test-small-asm` で既存命令の回帰確認、`make test-small-asm-labels` で前方・後方参照、全4命令のbyte列、命令挿入後の解決、エラーと上限、VM実行を確認する。VM本体やwriterは変更しない。テスト対象はツールなのでPythonから実際のsmall-asmを起動する。
